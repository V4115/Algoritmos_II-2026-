# 7. ¿Qué complejidad tiene Quicksort en promedio y en el peor caso? ¿Por qué?

| Caso | Complejidad |
|------|-------------|
| Mejor / Promedio | **Θ(𝑛 log 𝑛)** |
| Peor | **Θ(𝑛²)** |

## Peor caso: 𝑂(𝑛²)
Ocurre cuando el pivote es siempre el mínimo o el máximo (por ejemplo, arreglo ya ordenado con pivote en el primer o último elemento). La partición queda totalmente desbalanceada: un subproblema de tamaño 𝑛−1 y otro vacío.

> 𝑇(𝑛) = 𝑇(𝑛−1) + 𝑂(𝑛) ⟹ 𝑇(𝑛) = 𝑛 + (𝑛−1) + ... + 1 = Θ(𝑛²)

## Mejor caso y caso promedio: 𝑂(𝑛 log 𝑛)
Si el pivote parte el arreglo en mitades parejas:

> 𝑇(𝑛) = 2𝑇(𝑛/2) + 𝑂(𝑛) ⟹ Θ(𝑛 log 𝑛)

En el caso promedio las particiones no son perfectas, pero **alcanza con que sean razonablemente balanceadas**: incluso una partición 9:1 en cada paso da profundidad log_{10/9} 𝑛 = 𝑂(log 𝑛) con 𝑂(𝑛) de trabajo por nivel, o sea 𝑂(𝑛 log 𝑛). Con pivote aleatorio, las particiones muy malas son poco probables.

## Cómo evitar el peor caso
- Elegir el pivote **al azar**.
- Usar **mediana de tres** (primero, medio, último).
