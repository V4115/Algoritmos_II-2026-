# 8. ¿Por qué la medición empírica del tiempo puede ser engañosa?

1. **Depende del entorno**: CPU, caché, memoria, temperatura, otros procesos, planificador del SO.
2. **Depende de la implementación**: lenguaje, compilador, optimizaciones, JIT, recolector de basura (*warm-up*, pausas de GC).
3. **Ruido y resolución del reloj**: tiempos muy chicos se confunden con la variabilidad del sistema.
4. **Las constantes ocultan el comportamiento asintótico**: por ejemplo, `100·n` es más lento que `n²` para 𝑛 < 100. Con 𝑛 chico se puede concluir lo contrario a lo que pasa en general.
5. **Entradas no representativas**: se mide con unas pocas entradas y se pueden pasar por alto el mejor o el peor caso (ej.: Quicksort sobre datos aleatorios vs. ya ordenados).
6. **No permite extrapolar con seguridad** a tamaños mayores a los probados (efectos de caché, swapping, etc.).
7. **Poca reproducibilidad**: otro equipo o otro momento dan otros números.

## Buenas prácticas si igual se mide
- Repetir varias veces y usar mediana o promedio.
- Probar con distintos tamaños (*doubling test*: duplicar 𝑛 y ver cómo crece el tiempo).
- Usar entradas de distintos tipos (aleatorias, ordenadas, inversas).
- **Complementar siempre con el análisis teórico.**
