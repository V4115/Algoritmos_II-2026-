# 2. ¿Por qué agregar al final de un vector es 𝑂(1) amortizado? ¿Y si agrandáramos de a uno?

## Costo de un `add` al final
- Si hay lugar (`size < capacity`): se escribe en la siguiente posición → **𝑂(1)**.
- Si está lleno: se crea un arreglo nuevo, se copian los 𝑛 elementos y se agrega → **𝑂(𝑛)**.

## Por qué es 𝑂(1) amortizado (capacidad se duplica)
Las copias caras ocurren cuando el tamaño es 1, 2, 4, 8, ..., y cada una cuesta lo que vale ese tamaño. Para 𝑛 inserciones:

> Costo total de copias ≤ 1 + 2 + 4 + ... + 𝑛/2 + 𝑛 < **2𝑛**

Más las 𝑛 escrituras: costo total = 𝑂(𝑛) para 𝑛 inserciones, es decir, **𝑂(1) por inserción en promedio**. El costo de la copia "se reparte" entre las muchas inserciones baratas que la precedieron.

> Una operación puntual puede costar 𝑂(𝑛), pero **cualquier secuencia de 𝑛 inserciones** cuesta 𝑂(𝑛) en total.

## Si agrandáramos de a uno
Cada `add` encuentra el arreglo lleno y copia todo:

> 1 + 2 + 3 + ... + 𝑛 = 𝑛(𝑛+1)/2 = **𝑂(𝑛²)** en total → **𝑂(𝑛)** por inserción.

Lo mismo pasa si crece una cantidad **constante** 𝑘 cada vez: se copian 𝑛/𝑘 veces, y el total sigue siendo 𝑂(𝑛²). Para que sea amortizado 𝑂(1), el crecimiento tiene que ser **proporcional** (multiplicar por un factor, ej. ×2 o ×1,5).
