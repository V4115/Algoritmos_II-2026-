# 11. ¿Por qué hoy se usa ArrayList y no java.util.Vector? ¿En qué se diferencian?

Ambos son vectores dinámicos respaldados por un arreglo, pero `Vector` es de Java 1.0 (anterior al Collections Framework) y quedó como **clase legacy**.

| | ArrayList | Vector |
|---|---|---|
| Sincronización | **No** sincronizado | Métodos **`synchronized`** |
| Rendimiento | Mejor (sin costo de locks) | Peor, incluso con un solo hilo |
| Crecimiento | ~×1,5 de la capacidad | ×2 por defecto (o `capacityIncrement`) |
| API | Moderna (`List`) | Además tiene métodos viejos (`addElement`, `elementAt`, `capacity()`...) |
| Uso actual | Estándar | Desaconsejado |

## Por qué se prefiere `ArrayList`
- La mayoría de los programas no comparten la lista entre hilos, y pagar la sincronización en cada llamada es **un costo innecesario**.
- La sincronización por método de `Vector` **no alcanza** para operaciones compuestas (ej.: "si no está, agregar"), que igual requieren sincronización externa. Da una falsa sensación de seguridad.

## Si se necesita concurrencia
Usar `Collections.synchronizedList(new ArrayList<>())`, `CopyOnWriteArrayList` u otras colecciones del paquete `java.util.concurrent`.
