# 9. ¿Cuándo conviene un ArrayList y cuándo un LinkedList?

| Operación | ArrayList | LinkedList |
|---|---|---|
| `get(i)` / `set(i, x)` | **𝑂(1)** | 𝑂(𝑛) |
| `add` al final | **𝑂(1) amortizado** | 𝑂(1) |
| `add` / `remove` al inicio | 𝑂(𝑛) | **𝑂(1)** |
| Insertar / eliminar en el medio por índice | 𝑂(𝑛) | 𝑂(𝑛) (hay que llegar hasta ahí) |
| Insertar / eliminar con el iterador ya ubicado | 𝑂(𝑛) | **𝑂(1)** |
| Memoria por elemento | Baja | Alta (nodo con 2 punteros) |

## Conviene `ArrayList` cuando...
- Se accede mucho **por índice** o se recorre con frecuencia.
- Se agrega principalmente **al final**.
- Importa la memoria y la **localidad de caché** (elementos contiguos).

## Conviene `LinkedList` cuando...
- Se hacen muchas **inserciones/eliminaciones al inicio o en posiciones ya ubicadas** (por medio de un iterador).
- Se usa como **cola o deque** (aunque `ArrayDeque` suele ser mejor).

> En la práctica, **`ArrayList` es la opción por defecto**: el 𝑂(1) teórico de `LinkedList` en el medio se pierde porque hay que buscar la posición, y los nodos dispersos aprovechan mal la caché.
